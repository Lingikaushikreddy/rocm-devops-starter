# ROCm portability of 12 popular PyTorch repositories

Scanned 2026-09-23 with `rocm_portscan`. Static analysis only: nothing here
was run on AMD hardware, and a REVIEW finding means "a person should check
this", not "this is broken". Reproduce every number with
`scripts/run_survey.sh`, which fetches each repository at the commit below.

## What the numbers say

**One hard blocker in twelve repositories, and it is narrow.** NeMo's
`examples/voice_agent/environment.yaml` pins `cupy-cuda12x==13.6.0`. That is
one example's frozen conda environment, not NeMo's core install. Checked by
hand at the commit above.

**Plain PyTorch is not where porting breaks.** whisper and nanoGPT produce no
findings at all. Ordinary `torch.cuda` use (`.to("cuda")`,
`torch.cuda.is_available()`) is not flagged, because ROCm builds of PyTorch
answer to the same API. `init_process_group("nccl")` is not flagged either:
on ROCm it routes to RCCL.

**The work is in the acceleration libraries.** bitsandbytes appears in 7 of
the 12, flash-attn in 6, xformers in 5, custom CUDA sources in 4, apex in 3.
Each has a ROCm path of different maturity (ROCm/apex and
ROCm/flash-attention are maintained forks; `torch.utils.cpp_extension`
hipifies `CUDAExtension` sources automatically). The question per repository
is which version and which kernels, which a scanner can point at but not
answer.

**Hardcoded `float8_e4m3fn` shows up in 5 repositories.** This is the one
most likely to fail quietly. gfx942 (MI300) executes `e4m3fnuz`, which caps
at 240 and has no infinity; `e4m3fn` caps at 448. A value of 448 is ordinary
on H100 and becomes NaN in `e4m3fnuz`, and a `-inf` mask fill becomes NaN
too. Both conversions are checked on every push by `rocm_portscan/proofs.py`.

**`get_device_capability()` appears in 8 repositories**, mostly as gates
like `get_device_capability()[0] < 8` that encode NVIDIA generations. The
call works on ROCm, but the number it returns is not an NVIDIA compute
capability, so each gate needs checking.

## Hand checks done before publishing

- The single BLOCKER: opened the file at the scanned commit.
- REVIEW rules: at least three hits per rule opened and read.
- Noise found: ROCM004 (`sm_XX`) and ROCM106 (`--gpus`) also match
  `echo`/`print` text in shell scripts. They are REVIEW-tier pointers, and
  neither is in the table above.
- `Dao-AILab/flash-attention` was scanned and left out: it is the flash-attn
  project itself and ships its own ROCm backend, so its row would only count
  references to itself.
